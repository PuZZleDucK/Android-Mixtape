# Media notification tap checks on Kunlun API 24

Device: `kunlun.local` visible `emulator-5554`, Android API 24. App: `org.puzzleduck.mixtape`, modern debug APK built with `JAVA_HOME=/home/puzzleduck/.asdf/installs/java/temurin-21.0.10+7.0.LTS ANDROID_HOME=/home/puzzleduck/Android/Sdk ./gradlew assembleModernDebug`, then deployed with `./kunlun-sync.sh --install-app --start-app`. Existing scanned audio was present. Selected the first mixtape by tapping its spine at `(450,375)` to establish a media session. The checks below used the real Media3 shade notification, not an explicit `am start` intent. Coordinates are for the emulator's 1080 x 1920 screen.

Reproduce with `ssh kunlun.local`, setting `A=/home/puzzleduck/Android/Sdk/platform-tools/adb` and using `$A -s emulator-5554 shell` for each command. To inspect the actual screen, run `uiautomator dump /sdcard/window.xml` and `cat /sdcard/window.xml`; `dumpsys activity activities | grep mResumedActivity` identifies the resumed Activity.

1. Warm Activity: `input keyevent HOME`, then `input swipe 500 0 500 1150 600`. The shade showed Mixtape, Restored Track 01, Seek to previous item, and Play. Tapping transport Play at `(970,360)` left `mCurrentFocus=StatusBar`. Tapping previous at `(830,360)` also left `mCurrentFocus=StatusBar`; the notification remained with a Play action. Tapping the notification body at `(450,350)` resumed the existing MainActivity record `479a9c7` in task `595`. The UI hierarchy contained `content-desc="Cassette deck"`. Transport taps did not open the Activity.
2. Cold Activity: with the shade dismissed, `input keyevent BACK` finished MainActivity; a second BACK left Launcher resumed. `dumpsys activity activities` had no MainActivity record. The Media3 notification remained posted under `org.puzzleduck.mixtape`, id `1001`, with Restored Track 01 and Play. Open the shade with `input swipe 500 0 500 1150 500`, then tap its body at `(450,350)`. A new MainActivity record `ceb7f65` appeared in task `596`, and the UI hierarchy again contained `content-desc="Cassette deck"`. The notification remained posted. This is a cold Activity launch while the media service stays alive, as required for a tappable notification.

Notification Play was visible immediately before the cold tap. This check establishes navigation and notification persistence, not position or playback-state continuity. The test did not use force-stop, which would remove the foreground media session and its notification. Screenshots `notification.png` and `now-playing-after-tap.png` cover the earlier paused warm tap; `cold-notification-tap.png` captures the fresh Activity after the cold tap. All screenshots come from the Kunlun emulator.
